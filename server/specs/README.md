# server/specs/

Plans for server work that is **not built yet** and stays inside
`@devdigest/api` — a new module, a schema change, an adapter.

A spec lands before the code. Once the work ships, either delete it or promote
the durable parts to `../docs/`.

Features that also change the client belong in the repo-root `../../specs/`.

Not here: how the server works today (`../README.md`, `../docs/`) or debugging
findings (`../INSIGHTS.md`).
