## Systemic patterns

1. **Clickable `<div>` for primary row/card navigation, with no keyboard fallback** — `PRRow` (REACT-2), `AgentCard` (REACT-3), and the `PromptBlock` header (REACT-6) all use `onClick` on a non-interactive element with zero `role`/`tabIndex`/`onKeyDown`. The codebase clearly *knows* the correct pattern — `ReviewRunAccordion.tsx:78-86` and `ToolCallRow.tsx:16-27` do it right, and `RunHistory.tsx:205-217` explicitly documents *why* its own row stays a keyboard-inaccessible `<div>` (a nested button provides the real keyboard path). PRRow/AgentCard have no such nested escape hatch, so the documented justification doesn't carry over to them.
2. **Custom dropdown/select primitives (`Dropdown`, `SearchableSelect`) lag the bespoke ones (`CommandPalette`, `SeverityFilterBar`) on a11y** — Escape-to-close, `aria-pressed`/`aria-expanded`, and keyboard-open support are present where a screen needed to build its own control, but missing from the shared `vendor/ui` primitives that most screens actually reach for.
3. **`Modal`/`Drawer` never got the dialog-semantics pass `Collapse` and `CommandPalette` got** — no `aria-labelledby`, no focus management, no Escape, in either primitive, across all 3 usages found.
4. **Query/mutation-driven state is handled correctly almost everywhere except `ConfigTab`** (REACT-1) — every other multi-field form/query surface (`RunHistory`, `FindingsPanel`, `FindingsTab`) already uses the render-time-adjustment or `useMemo`/derive patterns the skill asks for; `ConfigTab` is the one outlier still using the effect-based reset the rest of the codebase has moved away from.

## What's good

- `FindingsPanel`/`FindingsTab`/`RunHistory` (`_components/FindingsPanel`, `_components/RunHistory`) are textbook: render-time state adjustment for hand-offs (no effect-paints-stale-frame issue), `useMemo`'d lookup maps keyed correctly to keep `React.memo` on `SeverityIcons` intact, clamp-on-read for a stale focus index instead of a corrected copy in state.
- `FindingsPopover.tsx` — DOM event delegation via `data-severity` is deliberate and well-reasoned (matches `INSIGHTS.md`), full listener cleanup on unmount and on open/close transitions, portal rendered only while open so `useLayoutEffect` never hits SSR.
- `CommandPalette.tsx` is the reference implementation for a dialog in this codebase: `role="dialog" aria-label`, Escape, auto-focus, arrow-key roving selection — everything `Modal`/`Drawer`/`Dropdown` are missing.
- `ToolCallRow.tsx` / `ReviewRunAccordion.tsx` — correct `role="button" tabIndex aria-expanded aria-controls onKeyDown` disclosure pattern, consistently applied.
- `useRunEvents` (`lib/hooks/reviews.ts:177-225`) is a clean example of an effect that really does synchronize an external system (SSE), with full cleanup and no derived-state leakage.
