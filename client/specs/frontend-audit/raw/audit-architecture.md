## Systemic patterns (≥3 places)

1. **Thick `page.tsx`.** 4 of 7 pages hold state, hooks and branching (ARCH-1, 3, 4, 13). The anatomy doc and the skill both say "thin". The three pages that follow it (`agents/page.tsx`, `onboarding/page.tsx`, `settings/[section]/page.tsx`) are the template.
2. **Domain vocabulary duplicated per component, and it has already drifted.** Severity colours (3 tables; SUGGESTION accent vs sugg), severity order (3), verdict colours (2; comment warn vs info), status colours (2), `lineLabel` (3), `formatWhen` (2), blocker definition (2), needs-review count (2). See ARCH-7–10, 33–36. The fix is one owner per concept, and `SEV` in `@devdigest/ui` and `severity-icons/helpers.ts` already exist to fill that role.
3. **Inline copy concentrates in older "ported" files.** The newer L01 files (`FindingsPanel`, `SeverityFilterBar`, `RunCostValue`, `VerdictBanner`) are fully i18n'd. `AddRepoView`, `FindingsTab`, `ReviewRunAccordion`, `PrDetailHeader`, `agents/[id]/page.tsx`, `app/page.tsx` and several confirm dialogs are not (ARCH-20–27).
4. **Inline `style={{}}` and missing `styles.ts`** in the same ported files (ARCH-16–19). About 110 inline style blocks sit in app/components/lib. The same folders also lack `constants.ts`/`index.ts` (ARCH-15, 42).
5. **Missed promotions of repeated UI patterns**: the disclosure header (4×, plus 2 unconverted), the trash action (3×) and `PROVIDER_OPTIONS` (2 routes) (ARCH-30–32). Meanwhile diff-viewer was promoted with one consumer (ARCH-6). The promotion rule is being applied in both directions at once.

## ADR candidates (not direct fixes)

- **Query-key factory + `queryOptions()`**: ARCH-2 shows route code hand-typing keys. The key space is inconsistent (`["pull", id]` vs `["pulls", repoId]`, `["agent", id]` vs `["agents"]`), and `useFindingAction` invalidates the `["pulls"]` prefix while `["pull", id]` sits outside it. A factory in `lib/hooks/keys.ts` makes that visible. Cost: touches all 5 hook files.
- **Lint-enforced import boundaries** (`import/no-restricted-paths` or `eslint-plugin-boundaries`): no CRITICAL violations today, but the parent-route `_components` question (ARCH-5), the past-barrel import (ARCH-15) and 39 deep relative imports show the rule is enforced by review only. Decide the nested-route policy first.
- **Error-surface policy** (`MutationCache` global toast vs inline): three call sites double-report (ARCH-11). A `meta.errorSurface` convention is a cross-cutting decision that future hooks depend on.
- **i18n for design-system data and shared leaves**: `vendor/ui/nav.ts` labels, toast/provider fallbacks and the "shell" namespace reused by diff-viewer (ARCH-25, 27, 28). Decide whether `@devdigest/ui` stays copy-free (keys only) or ships default English.

## What's good

- The layer map holds: `fetch` appears only in `lib/api.ts:24`, every data hook lives in `lib/hooks/*`, and no component imports `apiFetch`.
- Newer components are textbook anatomy: `FindingsPanel` (`baseFindings`/`bySeverity` in `helpers.ts`, named, documented constants), `SeverityFilterBar` (`as const satisfies`), `RunCostValue` (a promoted leaf with 3 real consumers and its own namespace).
- The shared `severity-icons` / `findings-popover` tier has clean barrels, pure tested helpers (`helpers.test.ts`) and documented design decisions.
- Query policy lives in the hooks: polling via `refetchInterval` functions (`reviews.ts:33,45`), and cache sharing is deliberate (`usePrReviews` key reuse, `reviews.ts:58-61`).
- `vendor/ui` imports no feature code (only react, lucide, recharts, markdown). The DS-editability line from ADR 0003 is respected.
