# client/specs/

Plans for studio work that is **not built yet** and stays inside
`@devdigest/web` — a new screen, a navigation change, a component rework.

A spec lands before the code. Once the work ships, either delete it or promote
the durable parts to `../docs/`.

Features that also change the API belong in the repo-root `../../specs/`.

Not here: how the studio works today (`../README.md`, `../docs/`) or debugging
findings (`../INSIGHTS.md`).
